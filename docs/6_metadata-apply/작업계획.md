# 메타데이터 적용 및 결과 처리 작업계획

## 목표

MetadataScreen의 `메타데이터 수정하기` 버튼에 실제 저장 로직을 연결한다.
체크된 필드만 선별해 `MetadataService.write_tags()`를 파일별로 호출하고,
성공·실패 결과를 사용자에게 알림으로 표시한 뒤 적절한 화면 전환을 수행한다.

## 작업 범위

- `screens/metadata.py` — 수정 버튼 클릭 핸들러 구현
- `MetadataService` 연동 (기존 `write_tags()`, `clean_track_title()`, `assign_track_numbers()` 활용)
- 성공 시 Toast 알림 + 탐색 화면 복귀
- 실패 시 Toast 알림 + 메타 화면 유지

---

## 세부 작업 목록

### 1단계: 체크된 항목 수집 및 태그 딕셔너리 구성

- [x] 수정 버튼 클릭 시 각 필드 체크박스 상태 확인
- [x] 체크된 필드만 포함한 `tags` dict 구성
  - `cb-album` 체크 → `tags["album"]` = `#input-album` 값
  - `cb-artist` 체크 → `tags["artist"]` = `#input-artist` 값
  - `cb-year` 체크 → `tags["year"]` = `#input-year` 값
  - `cb-title` 체크 → `tags["title"]` = `MetadataService.clean_track_title(파일명)`
  - `cb-track-number` 체크 → `tags["track_number"]` = `MetadataService.assign_track_numbers()` 순번

### 2단계: MetadataService 호출 및 결과 수집

- [x] `MetadataService` 인스턴스 생성 (또는 앱 레벨에서 공유)
- [x] `selected_files` 순회하며 파일별 `write_tags(filepath, tags)` 호출
  - 트랙명은 파일마다 `clean_track_title(파일명)`으로 개별 계산
  - 트랙번호는 `assign_track_numbers(selected_files)` 결과에서 순번 매핑
- [x] 실패한 파일 목록 수집

### 3단계: 결과 알림 및 화면 처리

- [x] 전체 성공 시: `self.app.notify("메타데이터 수정 완료!")` Toast 표시 후 `self.app.pop_screen()`으로 탐색 화면 복귀
- [x] 일부 또는 전체 실패 시: `self.app.notify("일부 파일 수정 실패", severity="error")` Toast 표시 후 메타 화면 유지

## 완료 기준

- `메타데이터 수정하기` 버튼 클릭 시 체크된 필드만 선택된 MP3 파일들에 ID3 태그로 저장된다.
- 트랙명은 파일명 기반으로 자동 정제되어 저장된다.
- 트랙번호는 파일명 오름차순 순번으로 저장된다.
- 전체 성공 시 Toast 알림과 함께 탐색 화면으로 자동 복귀한다.
- 실패 파일이 있을 경우 에러 Toast가 표시되고 메타 화면이 유지된다.
