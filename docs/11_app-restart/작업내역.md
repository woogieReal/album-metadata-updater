## [2026-09-19] 앱 재실행(코드 리로드) 기능

### 작업 내용
- 개발 중 코드를 수정할 때마다 터미널을 닫고 앱을 재실행해야 했던 번거로움을 없애기 위해, 앱 안에서 프로세스를 재기동하는 기능을 추가함
- `AlbumTagApp`에 전역 단축키 `Ctrl+R`을 추가하고, 누르면 `restart_requested` 플래그를 세운 뒤 `App.exit()`로 Textual을 정상 종료하도록 구현
- `main.py`에서 `app.run()` 종료 후 `restart_requested`가 참이면 `os.execv(sys.executable, [sys.executable] + sys.argv)`로 같은 프로세스를 재실행하도록 구현 — 파이썬이 모든 모듈을 디스크에서 새로 import하므로 저장된 코드 변경이 반영됨
- `ExplorerScreen` 하단바에 "앱 재시작" 버튼을 추가하고, 클릭 시 `Ctrl+R`과 동일한 `action_restart_app()`을 호출하도록 연결

### 주요 결정 사항
- **`os.execv`를 앱 안에서 바로 호출하지 않고, `App.exit()`로 정상 종료 후 `main.py`에서 재실행하는 2단계 구조를 택함**: Textual은 실행 시 터미널을 alt-screen/raw mode로 전환하는데, 종료 절차 없이 프로세스를 바로 갈아치우면 터미널 상태 복구 없이 화면이 깨질 위험이 있었음. `exit()`로 정상 종료 → 터미널 복구 → 그 다음 `execv`로 재실행하는 순서를 지켜 안전하게 처리함
- **재시작 단축키를 `r`이 아닌 `Ctrl+R`로 선택**: `ExplorerScreen`이 이미 `r`을 "파일 트리 새로고침"(`action_refresh`)으로 쓰고 있어 겹치지 않는 키가 필요했음
- **버튼 핸들러가 별도 로직 없이 `Ctrl+R`과 동일한 `action_restart_app()`을 호출**: 두 트리거(단축키/버튼)가 같은 코드 경로를 타게 해 동작을 일관되게 유지하고 중복 구현을 피함

### 이슈 & 해결
- 인터랙티브 TUI 특성상 정적 코드 검토만으로는 "재실행 시 터미널이 깨지지 않는지"를 확인할 수 없었음 → `tmux`로 실제 pty 세션을 열어 `python main.py`를 구동하고 `Ctrl+R`을 직접 전송해 실측 검증함. 재실행 전/후 프로세스 PID가 동일하게 유지되고, `TITLE` 문구를 임시로 바꿔 저장한 뒤 재실행하니 변경 사항이 즉시 반영되는 것을 확인함. 테스트 중 이미 실행 중이던 별도의 사용자 프로세스(다른 tty)는 건드리지 않도록 격리해서 진행함
- `MetadataScreen`에서의 `Ctrl+R` 동작은 실측하지 않음 — 해당 화면에 별도 `BINDINGS`가 없어 Textual의 바인딩 해석 순서(위젯 → 스크린 → 앱)상 앱 레벨 바인딩으로 정상 위임될 것으로 판단해 잔여 리스크로 남겨둠

### 변경 파일
- `app.py`: `restart_requested` 플래그, `Ctrl+R` 바인딩, `action_restart_app()` 추가
- `main.py`: `app.run()` 이후 재시작 플래그 확인 및 `os.execv` 재실행 로직 추가
- `screens/explorer.py`: 하단바에 "앱 재시작" 버튼 및 클릭 핸들러 추가
- `docs/11_app-restart/`: 작업계획.md, 검증결과.md, 작업내역.md
