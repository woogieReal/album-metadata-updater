## [2026-07-30] MetadataScreen 구현

### 작업 내용
- `requirements.txt`에 `xattr` 패키지 추가 및 `.venv` 설치 (xattr 1.3.0)
- `docs/blueprint.md` 수정 — 앨범명·아티스트·연도의 1차 읽기 출처를 "MP3 메타데이터"에서 "선택된 폴더의 xattr(`user.album`, `user.artist`, `user.year`)"로 정정
- `screens/metadata.py` — `MetadataScreen` 전체 구현
  - `compose()`: 우상단 닫기 버튼, 중앙 메타데이터 설정 영역(ScrollableContainer), 하단 수정 버튼 배치
  - `on_mount()` → `_load_folder_metadata()`: `app.selected_folder`의 xattr 읽기, `user.album` 없으면 폴더명으로 fallback
  - `on_checkbox_changed()`: `전체 항목 선택/해제` 토글 시 5개 필드 체크박스 일괄 연동
  - `on_button_pressed()`: 닫기 → `pop_screen()`, 수정 버튼 → Phase 6에서 구현 예정

### 주요 결정 사항
- 1차 읽기 출처를 MP3 ID3 태그가 아닌 **폴더 xattr**으로 결정
  - yt-music-downloader가 다운로드 시 폴더에 `user.artist`, `user.year` xattr을 저장하는 구조이기 때문
  - 이 앱의 제작 동기 자체가 "Finder에서 파일명은 수정했지만 ID3 태그를 못 고쳤던 것"을 해결하기 위함이므로, 폴더 xattr이 신뢰할 수 있는 정보 원천
- `_read_xattr()`을 별도 메서드로 분리해 `KeyError` 및 디코딩 예외를 안전하게 처리
- `FIELD_CBS` 상수 리스트로 전체 선택/해제 대상 체크박스 ID를 선언적으로 관리
  - 추후 필드 추가·제거 시 리스트 한 줄만 수정하면 되도록 유지보수성 확보
- 트랙명·트랙번호는 입력창 없이 안내 `Label`만 표기 (`color: gray`)
  - 자동 처리되는 값이므로 사용자가 직접 입력할 필요 없음을 UI로 명확히 전달

### 이슈 & 해결
- blueprint에 1차 읽기 출처가 "MP3 메타데이터"로 잘못 기재되어 있었음
  - 사용자 확인을 통해 폴더 xattr(`user.*`)이 올바른 출처임을 확정하고 blueprint 수정
